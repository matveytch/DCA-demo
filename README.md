# DCA — Document Creation Automation (демо)

Программа на Mac собирает пакет документов сделки из одного Excel-файла.
Оператор заполняет Excel и дважды щёлкает runner. Программа делает документы Word (RU/EN),
пакет приложений со сканами, ZIP и ведёт реестр партий.

Это обезличенная демо-версия. Предметная область абстрактная (стороны А, Б, В, изделие, партии),
все данные и шаблоны выдуманы и созданы скриптом.

## Что показывает движок

- **Строгие шаблоны Word** (`docxtpl`): условные абзацы, строки таблиц по данным, неизвестная переменная — ошибка.
- **Точные деньги:** `Decimal`, округление вверх в одной точке, сумма прописью на двух языках.
- **Русский язык:** даты в 7 форматах, склонение по числу и падежу названия компании.
- **Excel как интерфейс:** справочники с выпадающими списками, понятные ошибки «поле, лист, строка».
  Структуру книги меняет правка XML, поэтому выпадающие списки не ломаются.
- **Надёжная публикация:** сборка во временной папке, прежний результат — в архив, сбой ничего не портит.
- **Учёт:** реестр партий с формулами «Баланса» и проверкой строк, введённых вручную.
- **Графы фиксированной ширины:** движок сам раскладывает текст по строкам и отказывает, если текст не помещается.
- **Бэкап:** зашифрованные версии данных через restic, расписание macOS.

## Как запустить

Нужен Python 3.11 или новее.

```bash
python3 -m pip install -r requirements-lock.txt
python3 -m pytest
```

Пример сделки от начала до конца (данные попадут в `workspace/`, папка в `.gitignore`):

```bash
./dca new 1-2026-1705
cp data/input_example_FILLED.xlsx "workspace/Новые сделки/1-2026-1705_pending/input_1-2026-1705.xlsx"
./dca generate "workspace/Новые сделки/1-2026-1705_pending"
```

Результат — в `workspace/Компания А/Outgoing/1-2026-1705_1000kg/output_1-2026-1705/`.
Без сканов в `workspace/Data/scans/` программа покажет жёлтый блок «ПРОВЕРЬТЕ» — так и задумано.

Другие команды: `./dca --help`. Шаблоны и Excel-файлы пересоздаёт `python3 scripts/make_demo_templates.py`.

## Как устроена обвязка для Claude Code

Проект ведётся вместе с Claude Code. Обвязка держит сессию в рамках задачи:

1. **Требования** — [docs/requirements.md](docs/requirements.md): что строим, правила, критерии приёмки.
   Новое уточнение пользователя сначала попадает сюда, потом в код.
2. **Тесты** — [docs/tests.md](docs/tests.md): правила и карта «критерий приёмки → тест».
   Галочка у критерия — только после зелёного теста. CI на GitHub запускает набор на каждый push.
3. **Хук** — [.claude/hooks/stay_in_repo.py](.claude/hooks/stay_in_repo.py): не даёт сессии читать
   и писать файлы вне репозитория. Хук проверен тестами (`tests/test_claude_hook.py`).
4. **CLAUDE.md** — [CLAUDE.md](CLAUDE.md): порядок чтения документов, правила работы, git, задачи в Issues.

Архитектура и границы частей — [docs/architecture.md](docs/architecture.md).
