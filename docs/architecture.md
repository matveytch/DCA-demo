# Архитектура: DCA

Из каких частей собран проект и где границы между ними. Актуально на 2026-11-09.

Когда приходит новая задача, опирайтесь на этот документ. Не переписывайте архитектуру целиком.

## Как устроено (путь сделки)

```
Оператор
  │  заполняет Excel сделки (input_<номер>.xlsx), дважды щёлкает runner (*.command)
  ▼
Запуск: runner → dca (cli.py)
  ▼
Чтение ввода: excel_io → models (Deal, проверки) ← снимок базы Data/master_db.xlsx
  ▼
Расчёт: context (даты, деньги в Decimal, суммы прописью, склонение, строки граф акта)
  ▼
Сборка: render (.docx через docxtpl), attachments (сканы), archive (ZIP)
  ▼
Публикация: output_<номер>/ целиком, прежний → _archive/vN/; сделка → <компания>/Outgoing|Incoming/
  ▼
Учёт: ledger → Data/batch_ledger.xlsx («Транзакции», «Баланс»)
```

## Из каких частей состоит

| Часть | Что делает | Где |
|---|---|---|
| **Интерфейс оператора** | Ввод данных и запуск. Графического интерфейса нет | Excel-шаблон `data/input_template_EMPTY.xlsx` (листы «Сделка», «Передача», «Изменение», «Приложения», справочники, «Превью»); runner'ы `*.command` в папке сделки; команды `dca …`; скрипт `./dca` |
| **Команды** | Разбор команд, общий порядок работы, сообщения оператору | `cli.py` |
| **Модель и проверки** | Данные сделки и бизнес-правила ввода | `models.py` (`Deal`, `AnnexLine`, `TransferInfo`, `AmendmentInfo`) |
| **Чтение и правка Excel** | Чтение листов в модель; правка структуры книги без потери выпадающих списков | `excel_io.py`, `xlsx_patch.py`, `master_db.py`, `utils/atomic.py` |
| **Расчёт контекста** | Всё, что печатается: даты в 7 форматах, деньги, прописью, склонение, строки граф акта | `context.py`, `utils/declension.py`, `utils/i18n.py`, `utils/textfit.py` |
| **Сборка документов** | Заполнение шаблонов строго (неизвестное имя — ошибка) | `render.py` |
| **Пакет приложений** | Поиск и копирование сканов, карточка компании, ZIP | `attachments.py`, `archive.py` |
| **Мягкие проверки** | Жёлтый блок и `❗ПРОВЕРЬТЕ.txt` — только о настоящих проблемах | `checks.py`, `_show_notices` в `cli.py` |
| **Реестр партий** | Списания партий, «Баланс», проверка ручных строк | `ledger.py` |
| **Целостность сделки** | Паспорт сделки, блокировка папки, версия подписанных документов, снимок `log.json` | `deal_identity.py`, `signatures.py`, `log.py` |
| **Расположение** | Где код, где данные; работа после переноса папки | `paths.py`, `config.py` |
| **Бэкап** | Зашифрованные версии данных, расписание, восстановление | `backup.py` |
| **Шаблоны документов** | Текст и вёрстка документов | `templates/` (5 `.docx`), создаёт `scripts/make_demo_templates.py` |
| **Обвязка для Claude** | Правила сессии, требования, тесты, граница папки | `CLAUDE.md`, `docs/`, `.claude/hooks/stay_in_repo.py`, `.claude/settings.json` |

## Шаблоны

| Шаблон | Что показывает в движке |
|---|---|
| `agreement.docx` | Условные абзацы (`{%p if deal_kind … %}`, `{%p if variant == "B" %}`), строки таблицы по приложениям (`{%tr for %}`), даты в разных форматах, склонение названия компании, сумма прописью RU/EN |
| `annex.docx` | Один файл на каждое приложение со своим номером, количеством и итогом |
| `amendment.docx` | Номера пунктов считает движок; неизменные пункты не печатаются |
| `transfer_act.docx` | Графы фиксированной высоты: движок раскладывает текст по строкам сам |
| `cover_list.docx` | Нумерация счётчиком Jinja; та же нумерация — в именах сканов пакета приложений |

## Где данные

| Данные | Где | В git |
|---|---|---|
| Код, шаблоны, тесты, документация | этот репозиторий | да |
| Сделки | `<данные>/Новые сделки/`, `<данные>/<компания>/Outgoing|Incoming/<сделка>/` | нет |
| База справочников | `<данные>/Data/master_db.xlsx` (+ версии `Data/_master_db_versions/`) | нет |
| Реестр партий | `<данные>/Data/batch_ledger.xlsx` (+ версии `Data/_ledger_versions/`) | нет |
| Сканы партий | `<данные>/Data/scans/` | нет |
| Карточка компании | `<данные>/<компания>/company_profile.<расширение>` | нет |
| Бэкап | репозиторий restic (по умолчанию Google Drive, `DCA-backups`) | нет |
| Пароль бэкапа | Связка ключей macOS, служба `dca-backup` | нет |

`<данные>` — корень данных. `dca.toml` в коде указывает на `workspace/` (папка в `.gitignore`).
Другой корень задают маркер `.dca.toml`, переменная `DCA_HOME` или опция `--home` (порядок — в `paths.py`).

## Стек

- Язык: Python 3.13 (минимум 3.11).
- Библиотеки: `docxtpl` и `python-docx` (Word), `openpyxl` (Excel), `pydantic` (модель и проверки), `typer` (команды), `num2words` (суммы прописью), `python-dateutil` (даты), `filelock` (блокировки).
- Для разработки: `pytest`, `pytest-xdist` (параллельно), `pytest-cov`, `ruff`, `mypy`.
- Точные версии — `requirements-lock.txt`.
- Внешние бесплатные программы: restic (бэкап), `security` и `launchctl` macOS (пароль и расписание бэкапа).
- Платформа: macOS.

## Границы

- **Код и данные.** Код живёт в репозитории. Данные оператора — вне git. Реальные данные не попадают в шаблоны, примеры, тесты и документацию.
- **Шаблоны — договор с движком.** Имена `{{переменных}}` — публичный интерфейс. Меняете имя — синхронизируйте модель, контекст и скрипт шаблонов. Рендер строгий: неизвестное имя — ошибка, а не пустое место.
- **Excel оператора.** Значения читаются через `openpyxl`. Структуру книги (листы, строки) меняет только `xlsx_patch` правкой XML. Сохранение через `openpyxl` ломает выпадающие списки.
- **Запись книг.** Только атомарно: временный файл → проверка → версия → замена (`utils/atomic.py`). Книга открыта в Excel — отказ.
- **Деньги.** Итоги считаются только в `context._total_at_price` и `_amount_ctx` (`Decimal`, округление вверх в одной точке). `float` в итогах нет.
- **Экранирование XML.** Контекст экранируется один раз, на выходе (`context._escape_strings`), включая строки таблиц.
- **Публикация результата.** Сборка идёт в папке `_сборка_output_<номер>_<id>`. `output_<номер>/` заменяется только целиком. После переименования `_make_visible` снимает флаг «скрытый».
- **Команда по сделке** начинается с `_open_deal` (блокировка, вид сделки) и `_confirm_identity` (уникальный номер).
- **Внешние программы** вызываются только из `backup.py`. Их отсутствие — понятное сообщение с командой установки.
- **Граница для Claude.** Сессия работает только внутри репозитория. Это проверяет хук `.claude/hooks/stay_in_repo.py`.

## Что считаем «правильно собранным»

Новое поле ввода собрано правильно, только если пройдена вся цепочка:

1. Требование записано в `docs/requirements.md`.
2. Поле есть в модели (`models.py`) и в строке Excel-шаблона (`scripts/make_demo_templates.py`).
3. Контекст отдаёт его в нужном формате (`context.py`).
4. Шаблон использует его, имя совпадает.
5. Есть тест: от Excel до текста готового документа.
6. Документация обновлена.

Пропущено хоть одно звено — задача не закрыта.
