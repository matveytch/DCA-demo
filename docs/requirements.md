# Требования: DCA (Document Creation Automation)

Источник правды о задаче. Демо-версия, актуально на 2026-11-09.

Как вести этот файл:

- Записывайте новое уточнение задачи сюда, с датой. Потом меняйте код.
- Галочку `[x]` у критерия приёмки ставит Claude. Основание — проверка из `docs/tests.md`, не обещание.
- Не удаляйте старый текст. Помечайте устаревшее «устарело — сохранено для истории».

## Что строим

Программу на Mac. Программа собирает пакет документов сделки из одного Excel-файла.

- Оператор заполняет один Excel-файл сделки.
- Программа делает документы Word на двух языках (RU/EN), пакет приложений и реестр партий.
- Одинаковые данные всегда дают одинаковые документы.
- Исправить опечатку — значит поправить одну ячейку и запустить программу снова.

Предметная область демо — абстрактная: стороны А, Б, В, изделие, партии. Все данные выдуманы.

Уточнение, актуально на 2026-11-09:

- Пользователь поручил завершить проверку демо и подготовку репозитория.
- Строка авторства в README разрешена пользователем. Проверка остальных файлов сохраняется полностью.
- Поставка — полная папка проекта с шаблонами и примерами Excel.

Потоки:

| Поток | Команда | Результат |
|---|---|---|
| Исходящая сделка | `dca new`, `dca generate` | Соглашение, приложения (по одному файлу на приложение), опись приложений, пакет приложений (сканы), `log.json`, ZIP |
| Акт передачи | `dca transfer` (или вместе с `generate`) | Акт передачи с полями фиксированной ширины |
| Входящая сделка | `dca new-incoming`, `dca generate-incoming` | Соглашение и приложения |
| Изменение | `dca amend` | Приложения и изменение к соглашению |
| Реестр партий | `generate`, `dca check-ledger` | `Data/batch_ledger.xlsx`: списания партий и «Баланс» |
| База справочников | `dca init-db`, `dca upgrade-db`, `dca refresh-db` | `Data/master_db.xlsx` и её снимок в каждой новой сделке |
| Бэкап | `dca backup`, `dca restore` | Зашифрованные версии данных (restic) |

## Для кого

| Роль | Что нужно |
|---|---|
| Оператор | Заполнить Excel, дважды щёлкнуть runner, получить пакет без ошибок |
| Хозяин шаблонов | Править шаблоны в Word, почти не трогать код |
| Получатель документов | Получить точные документы: ошибка в сумме или реквизитах стоит денег |

Оператор не программист. Программа называет ошибки ввода по-русски: что не так, на каком листе, в какой строке.

## Правила

Данные и ввод:

- Ввод — Excel-файл сделки (`input_<номер>.xlsx`).
- Справочники (стороны А, стороны Б, изделия, партии) программа копирует из базы `Data/master_db.xlsx` в момент создания сделки.
- Номер соглашения уникален на все компании. Повтор — отказ.
- Программа поддерживает только **кг** и **USD**. Другие единицы и валюты — понятная ошибка.
- Сторона А исходящей сделки — одна из наших компаний. Сторона Б входящей сделки — одна из наших компаний. У каждой нашей компании своя папка.
- Вид сделки (исходящая или входящая) задаёт команда, а не Excel.

Вариант исполнения:

- Поле `variant` на листе «Сделка»: A или B. Для исходящей сделки поле обязательно.
- При варианте B соглашение содержит раздел «Сторона В». Поля `party_c_name`, `party_c_address`, `party_c_details` обязательны.
- При варианте A раздела нет. Остальной текст соглашения не зависит от варианта.

Деньги и числа:

- Цена печатается так, как введена, все знаки.
- Итог = ceil(ceil(количество) × цена), в точной арифметике `Decimal`. Округление вверх — в одной точке.
- Количество печатается целым числом кг, округление вверх.
- Сумма прописью — RU и EN.
- Несколько приложений: итог соглашения равен сумме итогов приложений.

Сроки:

- Поле `due_date` — срок исполнения и срок действия соглашения. Пустое поле: дата соглашения + 2 месяца.
- Противоречие дат — предупреждение, документы создаются. Случаи: `due_date` раньше даты соглашения; дата приложения позже `due_date`; дата передачи позже `due_date`. Совпадение дат — не противоречие.

Предупреждения:

- Предупреждение — только о настоящей проблеме. Частое предупреждение о нормальном состоянии приучает оператора не читать предупреждения.
- Незаполненная «Передача» — норма, не предупреждение.
- Если проверять нечего, файла `❗ПРОВЕРЬТЕ.txt` нет и жёлтого блока нет.
- Перерасход партии — предупреждение, не отказ.

Безопасность данных:

- Повторный запуск не портит прежний результат: старое уходит в `_archive/vN/`, новое появляется только целиком.
- Временная папка сборки называется `_сборка_output_<номер>_<id>`. Имя не начинается с точки.
- Запись в книгу Excel — только атомарно. Если книга открыта в Excel — отказ.
- Программа не трогает подписанные файлы в `signed_<номер>/`. Документы изменились после подписи — предупреждение.
- Реальные данные никогда не попадают в шаблоны, примеры, тесты и документацию.

Окружение:

- Только macOS. Только бесплатные средства.
- Данные остаются на Mac оператора. Исключение — зашифрованный бэкап.
- Перенос папки проекта не ломает работу.

## Критерии приёмки

Каждый пункт проверяемый. Галочки ставятся на шаге проверки (`docs/tests.md`).

Исходящая сделка:

- [x] AC1: `dca new <номер>` создаёт папку в «Новые сделки» с Excel и runner'ами. Справочники — снимок базы. Повтор номера — отказ.
- [x] AC2: `generate` на заполненной сделке делает соглашение, приложения, опись, `log.json`, ZIP. Сделка переезжает в `<компания>/Outgoing/<номер>_<количество>kg/`.
- [x] AC3: Пустое обязательное поле или неверное значение — код выхода не 0, одно сообщение по-русски со всеми проблемами (поле, лист, строка). Частичных документов нет.
- [x] AC4: Итог = ceil(ceil(количество) × цена) в `Decimal`. Пример: 100 кг × 0,07 = 7,00, не 8.
- [x] AC5: Единица не кг или валюта не USD — понятная ошибка.
- [x] AC6: Повторный `generate` переносит прежний результат в `_archive/vN/`. Сбой при сборке или публикации оставляет прежний результат без изменений.
- [x] AC7: Несколько приложений: сумма их количеств равна количеству соглашения, иначе ошибка. На каждое приложение — свой файл.

Пакет приложений и реестр партий:

- [x] AC8: `generate` копирует сканы партий и карточку компании в `attachments_<номер>/` с номерами, как в описи.
- [x] AC9: Нет скана, неполная партия, партия другой компании — предупреждение в жёлтом блоке и в `❗ПРОВЕРЬТЕ.txt`. Полная сделка — ни того ни другого.
- [x] AC10: Реестр получает одну строку на пару «сделка × партия». «Баланс» показывает количество, списание, остаток. Перерасход — предупреждение.
- [x] AC11: «Баланс» сгруппирован по компаниям: первой идёт компания с большим числом открытых партий. Партии из базы без списаний — светло-зелёные.
- [x] AC12: `dca check-ledger` находит ошибки ручных строк (номер, `use_kg` текстом, ключ, количество партии) и не меняет файл. Без ошибок — пересобирает «Баланс».

Акт передачи:

- [x] AC13: `dca transfer` делает акт передачи из листа «Передача». Неполный лист — список всех пустых полей, файлов нет.
- [x] AC14: Незаполненная «Передача» при `generate` — без предупреждения. Заполненная с ошибкой — предупреждение.
- [x] AC15: Текст, который не помещается в графу акта, — отказ со списком всех граф. Программа не обрезает текст молча.

Другие потоки:

- [x] AC16: Входящая сделка — соглашение и приложения, без реестра и пакета приложений. Сделка переезжает в `<компания>/Incoming/`.
- [x] AC17: `dca amend` заполняет изменение полностью: суммы, прописью, номера пунктов. Неизменные пункты не печатаются. Пустой или неполный лист — отказ, прежний результат не меняется.
- [x] AC18: `dca from-log` воспроизводит пакет из `log.json`. Более новая версия лога — отказ. Изменился шаблон — предупреждение.
- [x] AC19: Подписи в `signed_<номер>/` к прежней версии документов — предупреждение до замены подписей.

Надёжность:

- [x] AC20: Книга открыта в Excel — программа не пишет в неё и говорит, что сделать.
- [x] AC21: Runner'ы работают после переноса папки проекта, без установки.
- [x] AC22: `dca backup` делает зашифрованную версию, хранит 7 дневных, 4 недельных, 12 месячных. `--test-restore` проверяет копию. Восстановление — только в новую папку.

Шаблоны и результат:

- [x] AC23: Вариант B добавляет в соглашение раздел «Сторона В» на RU и EN. Вариант A его не содержит. Остальной текст совпадает слово в слово.
- [x] AC24: Смена номера соглашения и количества: сделка в новой папке, новый output полный, прежний `output_<старый>` в `_archive/`, runner'ы с новым номером, пустой `signed_<старый>` удалён, непустой оставлен с предупреждением.
- [x] AC25: После `generate` программа проверяет папку `output_<номер>` по итоговому пути. Нет папки или документов — красное сообщение, код выхода не 0. Каждый запуск пишет строку в `Data/_generate.log`. У `output_<номер>` нет флага «скрытый».
- [x] AC26: Противоречие дат (раздел «Сроки») — предупреждение в терминале и в `❗ПРОВЕРЬТЕ.txt`. Документы создаются.
- [x] AC27: Шаблон с переменной, которой нет в данных, — ошибка с именем переменной. Пустого места вместо текста нет.

## Чего не делаем

- Графический интерфейс: Excel достаточно.
- Валюты, кроме USD, и единицы, кроме кг.
- Проверку содержимого сканов: программа проверяет только имя файла.
- Юридическую сверку текстов RU/EN.
- Windows.
- Автоматическую подпись документов.

## Пример

Все данные выдуманы (`data/input_example_FILLED.xlsx`).

- Соглашение `1-2026-1705` от 17.05.2026, вариант B, 1000 кг × 0,45 USD → итог 450,00 USD («Four hundred fifty US dollars 00 cents»).
- Два приложения: 600 кг (270,00) и 400 кг (180,00). Две партии: П-001 (700 кг) и П-002 (300 кг).
- `generate` делает пакет, сделка переезжает в `Компания А/Outgoing/1-2026-1705_1000kg/`.
- Изменение: количество 1000 → 1200 кг, цена прежняя → новая сумма 540,00 USD, пункт о цене не печатается.
- Ошибка ввода: не выбрана сторона А → «party_a_key is required (pick party A from «Стороны А» dropdown)». Документов нет.
